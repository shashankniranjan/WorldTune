Two views of the same pipeline

The system-context view (HLD) shows which external feeds WorldPulse trusts and where the free/paid decision actually gets enforced. The data-layer view (LLD) shows the one rule the whole prediction engine depends on: nothing timestamped after as_of is ever visible to a prediction being made at as_of.

1. System context — who feeds WorldPulse, and where the gate sits

docs/HLD.md §3

Every external source is optional and interchangeable; the only thing downstream code ever sees is a WorldEvent. The mechanism worth seeing is the registry.py gate: it is the single place that decides "does this source run at all," based on whether a key is present and whether WORLDPULSE_MODE=free allows it — so a missing WORLDMONITOR_API_KEY is a normal, logged skip, never a crash.

2. Data layers — the as_of wall a prediction can never see past

docs/LLD.md §1

A WorldEvent passes through six layers before it becomes a scored outcome. The wall drawn at as_of is real code, not a diagramming convention: get_events_as_of and get_bars_as_of are the only two read paths the predictor uses, and both refuse any row timestamped after the cutoff. Just as important is what happens on the far side of resolution: the resolver only ever adds the four resolution fields to an existing row — it never touches the fields that were written at creation.
